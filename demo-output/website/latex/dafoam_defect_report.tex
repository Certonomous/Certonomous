\title{\bfseries A decomposition-dependent adjoint in DAFoam v5\\
\large and two adjacent defects of the MACH-Aero toolchain:\\
the IDWarp rotation guard, and the ILU conditioning wall}
\author{Certonomous CFD Lab}
\date{2026-08-05}

\begin{document}
\maketitle

\begin{abstract}
\noindent
On a 2{,}777-cell OpenFOAM case run under \artifact{dafoam/opt-packages:latest}
(DAFoam 5.0.0, OpenFOAM v2506), varying \emph{only} the mesh decomposition moves the
analytic \(\mathrm{d}C_D/\mathrm{d}(\mathrm{shape})\) gradient from
\(0.00054\%\) agreement with its own finite difference (\texttt{simple} 4x1x1) to
\(8.95\%\) disagreement (\texttt{scotch}, the shipped default), with the converged primal
invariant to five significant figures and the adjoint right-hand side invariant to
\(4.8\times10^{-6}\). The linear solve is not at fault: it converges cleanly
(\texttt{PetscConvergedReason: 2}, true residual \(1.7\times10^{-7}\) in the
unpreconditioned norm) and is unmoved by a tolerance tightened four decades. The
discriminating measurement is a cross-residual: the converged \texttt{scotch} adjoint
vector, permuted to serial ordering by integer \texttt{decomposePar} addressing and
evaluated under the serial reverse-AD operator, leaves a residual of \(329\times\lVert
b\rVert\) against that operator's own \(1.14\times10^{-4}\) floor --- concentrated in the
\(x\)-momentum rows of partition-interface cells. The parallel matrix-free
transposed-Jacobian product is not the transpose Jacobian of the residual it claims to
differentiate. We report the phenomenon, the discriminators that convicted the operator
and exonerated every other candidate, the localization, why no published verification
could have caught it, and two adjacent findings from the same forensic arc: an IDWarp
degenerate-branch guard that differentiates to a hard zero at exactly the state every
gradient evaluation uses (root-caused, patched in four lines, and answering a five-year-old
open upstream issue), and an ASM sub-block ILU factorization whose failure is broken by
the PETSc developers' own sanctioned escalation to complete LU. \textbf{Nothing in this
document has been filed upstream.}
\end{abstract}

\section{The decomposition-dependent adjoint}

\subsection{The phenomenon}

The case is A4, a coarse Ahmed body: 2{,}777 cells, snappyHexMesh-class grid with
refinement interfaces, \artifact{DASimpleFoam}, kOmegaSST, one FFD shape design variable.
The instrument is OpenMDAO's \artifact{check\_totals}, whose finite-difference column is
computed \emph{per run, inside that run's own} \artifact{check\_totals} --- not computed
once and reused. Only the decomposition varies across the rows of
Table~\ref{tab:phenomenon}; verified by \texttt{diff} of every run directory against the
source case (the np runs carry a byte-identical \artifact{runScript.py}; the \texttt{simple}
runs differ by exactly one inserted \artifact{decomposeParDict} daOption line; the tolerance
run by exactly the \artifact{gmresRelTol} value), and by reading the
\texttt{Decomposition method} line back out of each log.

Four properties of this table decide everything that follows.

\begin{enumerate}
\item \textbf{The primal does not move.} Converged baseline \(C_D\) spans
0.15296979--0.15297237 across \emph{all} configurations --- invariant to five significant
figures. np=1 and np=4 \texttt{scotch} differ by \(5.5\times10^{-7}\) absolute,
\(3.6\times10^{-6}\) relative: separately reconverged SIMPLE solves at
\artifact{primalMinResTol} 1e-4, i.e.\ reconvergence noise, four orders of magnitude below
the 8.95\% gradient shift. The \texttt{simple} arm --- the arm with the \emph{correct}
gradient --- differs from np=1 by \emph{more} than \texttt{scotch} does.
\item \textbf{The finite difference does not move meaningfully.} The FD column spans
(2.4178--2.4265)e-01, a 0.36\% spread, against an 8.95\% analytic excursion.
\item \textbf{Rank count is not the trigger.} np=2 \texttt{scotch} sits at the np=1 floor
(0.26\%); np=3 is catastrophic in one direction (6.05\%, analytic high) and np=4 in the
other (8.95\%, analytic low); np=4 \texttt{simple} 4x1x1 is the cleanest configuration in
the table. What changes between the dirty and clean rows is the \emph{shape and orientation
of the cut}.
\item \textbf{The solve is not the problem.} Tightening \artifact{gmresRelTol} from 1e-6 to
1e-10 costs 811 GMRES iterations instead of 719 and changes the answer by nothing. The
np=4 \texttt{scotch} solve reports \texttt{PetscConvergedReason: 2} at final true residual
\(1.749572\times10^{-7}\), and DAFoam's own solver configuration makes that literal:
\artifact{DALinearEqn.C} sets \texttt{KSPSetPCSide(PC\_RIGHT)} and
\texttt{KSPSetNormType(KSP\_NORM\_UNPRECONDITIONED)}, so ``converged in the unpreconditioned
norm'' means what it says.
\end{enumerate}

This is the signature of a \emph{converged wrong answer}. It is also the signature that
makes the defect survivable in production: nothing in the solver's own telemetry is
anomalous.

\subsection{The discriminators}

Four candidate carriers were named in advance and executed cheapest-first
(\artifact{DISCRIMINATORS\_A4\_decomposition\_mechanism.md}; run artifacts under
\artifact{/home/ubuntu/certonomous-runs/W4-a4-discriminators/}, with per-arm directories,
\artifact{ledger.txt}, \artifact{runScript\_w4.py}, \artifact{build\_maps.py},
\artifact{analyze\_mats.py}).

\paragraph{M3(a) --- the primal, exonerated at zero cost.} Point 1 above, plus this
session's own arms: baseline \(C_D\) 0.1529738 / 0.1529749 / 0.1529732 (np1 / scotch /
simple), and mapped primal \emph{state vectors} agreeing across decompositions at
\(2.0\times10^{-3}\) / \(2.8\times10^{-3}\) relative --- with the duplicated
processor-face \(\phi\) copies agreeing to \(2.7\times10^{-15}\), machine precision. That
last number does double duty: it validates the permutation used by every measurement below.

\paragraph{M3(b) --- the mesh-derivative chain, exonerated by measurement.} The
\artifact{dCD/dXv} capture hook (a real reverse seed on \artifact{DAFoamWarper}) was run at
all three decompositions with the warp finite-difference directional derivative
\artifact{dXv/dshape} computed identically in each arm:

\noindent
The hand composition equals the framework total to \(6\times10^{-9}\) in \emph{every} arm:
the warp/DVGeo leg composes exactly at np=4 too. The warp direction itself is
decomposition-invariant --- \artifact{dXv/dshape} mapped point-by-point via
\artifact{pointProcAddressing} matches np=1 at \textbf{0.0e+00} in both np=4 arms. What
differs is the captured \artifact{dCD/dXv} seed: mapped to np=1 point ordering, \texttt{scotch}
differs from np=1 by \textbf{38.4\%} in norm, \texttt{simple} by 3.1\%. The IDWarp/DVGeo leg
is exonerated; \artifact{dCD/dXv} is wrong because the \(\psi\) it contracts is wrong.

\paragraph{M2 --- coloring and preconditioner, exonerated by architecture and by
measurement.} Both \artifact{dRdWTPC} and the full assembled \artifact{dRdWT} were dumped in
all three arms and permuted to np=1 ordering. The diffs do not correlate with the defect:
full-\artifact{dRdWT} Frobenius diff \(4.8\times10^{-2}\) (\texttt{scotch}) against
\(5.4\times10^{-2}\) for \texttt{simple} --- \emph{the FD-exact arm}; PC diff
\(3.7\times10^{-4}\) against \(3.7\times10^{-3}\). This is a recorded negative, and the
reason it is uninformative is itself measured: at np=1 the assembled \artifact{dRdWT} applied
to \(\psi\) already disagrees with the AD product by \(230\times\lVert b\rVert\). The
assembled matrix is a crude finite-difference object; only the preconditioner is built from
it, which is precisely why the KSP operator is matrix-free. Diff operator \emph{actions},
not operator \emph{entries}.

Architecturally the exoneration is stronger still: in the Jacobian-free path the coloring
machinery builds only \artifact{dRdWTPC}, and a wrong preconditioner cannot move a
right-preconditioned GMRES solution that converged in the unpreconditioned norm
(\artifact{DALinearEqn.C:170,313}) --- which this solve did.

\paragraph{M1 --- the cross-residual, which convicts the operator.} Each arm's converged
adjoint \(\psi\) was dumped and permuted to np=1 global state ordering by an \emph{exact
integer map} built from \artifact{cellProcAddressing} / \artifact{faceProcAddressing} (sign
carried for flipped faces) plus DAFoam's own \artifact{AdjointIndexing} dumps
(\texttt{writeJacobians: ["adjointIndexing"]}) --- no coordinate matching anywhere in the
construction. The true residual \(\lVert A^{\mathsf T}\psi + b\rVert\) was then evaluated
under the \emph{serial} AD operator via \artifact{calcJacTVecProduct}.

Three decisive facts follow.

\begin{enumerate}
\item \textbf{The \texttt{scotch} \(\psi\) does not remotely satisfy the serial system}
--- \(329\times\lVert b\rVert\), 3.3 million times the np=1 floor --- while it satisfies
its \emph{own} \texttt{scotch}-evaluated operator, same instrument, same API, at
\(1.2\times10^{-3}\) relative, and the KSP that produced it reports final true residual
\(1.7\times10^{-7}\) (719 iterations, reason 2). Same vector, two operators, answers five
orders apart: \textbf{the operators differ.}
\item \textbf{The right-hand side is not the carrier.} \(b = \mathrm{d}C_D/\mathrm{d}W\)
mapped across decompositions is invariant to \(4.8\times10^{-6}\) (\texttt{scotch}) and
\(6.9\times10^{-6}\) (\texttt{simple}) relative.
\item \textbf{\(\lVert\psi\rVert\) is inflated \(16.5\times\) under \texttt{scotch}}
(0.541 against 0.033 np=1 and 0.018 simple) at identical \(\lVert b\rVert\). The extra
content sits in the pressure (0.52 against 0.031) and \(z\)-momentum (0.117 against 0.005)
adjoint blocks.
\end{enumerate}

\paragraph{Confounds closed.}
\emph{(a) Linearization state.} The cross-residual was re-evaluated with the np=1 operator
linearized at the \texttt{scotch} arm's own mapped state: \texttt{scotch} reads
\(6.004094\times10^{1}\), unchanged to six digits, while the np=1 control degrades only from
\(1.14\times10^{-4}\) to \(1.0\times10^{-3}\). The state confound therefore contributes at
the \(10^{-3}\) level, five orders below the signal --- and the \texttt{simple} arm's state
differs \emph{more} from np=1 than \texttt{scotch}'s does (\(2.8\times10^{-3}\) against
\(2.0\times10^{-3}\)) while its residual is 3{,}500 times smaller.
\emph{(b) Duplicated-\(\phi\) averaging in the \(\psi\) map.} Replacing the average by either
copy moves the residual by at most \(9.1\times10^{-3}\), four orders below the signal. This
bound was computed with the assembled matrix --- the instrument M2 discredits --- which the
original record did not disclose; the supervisor sweep found it and reproduced the number
exactly as \(\lVert A_{\mathrm{asm}}(\psi_{\mathrm{copy}}-\psi_{\mathrm{avg}})\rVert\). It is
immaterial by margin: even inflated by the full \(230\times\) assembled-vs-AD discrepancy the
bound stays roughly \(30\times\) below the 60.04 signal, and the duplicate copies disagree by
at most \(3.6\times10^{-4}\) to begin with. The confound stays closed; the instrument should
have been flagged.

\subsection{The objection this measurement must survive}

A knowledgeable reader will ask: is the \texttt{scotch} operator perhaps the \emph{exact}
adjoint of a different-but-equivalent parallel discretization? If decomposition changed the
discrete residual itself at processor boundaries, the \texttt{scotch} adjoint could be
consistent with \emph{its} residual while differing from serial, and its
\(1.2\times10^{-3}\) self-consistency would even fit that story.

It does not survive the finite-difference column. The FD in Table~\ref{tab:phenomenon} is
computed per run, inside each arm's own \artifact{check\_totals}. An adjoint that were the
exact adjoint of an equivalent parallel discretization would match the finite difference of
\emph{that} discretization. The \texttt{scotch} analytic 2.2086e-01 disagrees by 8.95\% with
its own decomposition's FD of 2.4258e-01. Combined with the fact that OpenFOAM processor
patches evaluate the same interior face fluxes --- no legitimate \(O(1)\) residual-function
difference is available --- and that \(b\) maps invariantly at \(4.8\times10^{-6}\), the
supported conclusion is the strong one: \textbf{the parallel operator is not the transpose
Jacobian of the residual it claims to differentiate.}

This gap was not acknowledged in the original mechanism record; the supervisor sweep found
it and closed it from the prior record (\artifact{VERIFICATION\_A4\_mechanism\_supervisor\_sweep.md},
\commit{8e0a08bc}, Axis 4). It is stated here in the body, not in a footnote, because it is
the first objection a maintainer will raise.

\subsection{Sign-convention provenance, stated against ourselves}
\label{sec:signconv}

The values in Table~\ref{tab:crossres} appear in no log, and the original record's caption
cited a log that contradicts them on its face. The instrument
(\artifact{runScript\_w4.py}, tasks \artifact{w4\_dump} / \artifact{w4\_crossres}) computes
\texttt{res = Atpsi - b}, whereas the system OpenMDAO seeds is \(A^{\mathsf T}\psi = -b\).
Every arm's log therefore prints the sign-degenerate \texttt{ratio=2.000000e+00} for its
own-operator check, and none of the record's own-operator numbers --- the
\(1.14\times10^{-4}\) floor, the \(1.2\times10^{-3}\) self-consistency, the
\(2.083\times10^{-5}\) --- appears in any log.

The tabulated values are exact offline sign corrections, \(\mathrm{res} + 2b\), recomputed
from the dumped vectors (\artifact{w4x\_res\_*.npy}, \artifact{w4\_Atpsi}, \artifact{w4\_b}).
The correction is exact, and the adversarial sweep reproduces every digit of it three
independent ways:

\begin{itemize}
\item \textbf{Recomputation from the dumps} with the sweep's own scripts: np=1
\(1.140697\times10^{-4}\), \texttt{scotch} \(3.288078\times10^{2}\) (absolute
\(6.004094\times10^{1}\), max entry 42.25), \texttt{simple} \(9.367397\times10^{-2}\).
\item \textbf{An independently rebuilt permutation}, constructed from
\artifact{cellProcAddressing} / \artifact{faceProcAddressing} and the
\artifact{AdjointIndexing} dumps by the sweep's own parsers, bit-for-bit identical to the
session's map in \texttt{tgt} and \texttt{sgn} --- and validated on a channel the original
session never used: the AdjointIndexing dumps carry cell and face centre coordinates, and
mapped np=4 coordinates match np=1 coordinates at \textbf{max \(\lvert\Delta xyz\rvert =
0.0\)} over all 26{,}149 (\texttt{scotch}) and 26{,}227 (\texttt{simple}) entries. Every entry
of the map is thereby validated exactly, independent of any solved field.
\item \textbf{A fresh serial container run}: a new case directory staged from the same
source, fresh serial primal, \artifact{w4\_crossres} applied to \(\psi\) vectors mapped by
the sweep's own permutation. Raw \texttt{scotch} ratio \(3.288139\times10^{2}\);
sign-corrected \(3.288078\times10^{2}\); np=1 control \(1.140697\times10^{-4}\);
\texttt{simple} \(9.367397\times10^{-2}\)
(\artifact{W4-a4-verify-audit/audit\_crossres.log}, 9~s, 0.30 core-min).
\end{itemize}

\noindent
The defensible citation for Table~\ref{tab:crossres} is therefore the dumped vectors plus the
stated sign correction --- not \artifact{d\_crossres.log}. Anyone reproducing this protocol
should fix the convention in the instrument rather than offline; \artifact{w4\_crossres2},
written later, has the sign right and its log matches its numbers.

\subsection{Localization}

The 60.04 cross-residual is not spread over the domain. By state group, \textbf{59.78 of the
60.04 norm sits in \(U_0\) (\(x\)-momentum) rows}. By cell, entries with \(\lvert r\rvert >
0.5\) number 15, of which \textbf{13 sit on \texttt{scotch} partition-interface cells and 2 at
graph distance one} --- none farther. All 15 sit on \artifact{cellLevel} 0 cells, away from the
mesh's refinement interfaces. The two worst (42.25 and 42.24) sit at \(y = -0.1947\) and
\(y = +0.1949\): the \(y\)-normal cut signature.

Three structural facts sharpen this.

\begin{itemize}
\item \textbf{It is not a many-rank corner effect.} The worst cells each touch exactly
\emph{one} foreign rank through exactly \emph{one} processor face; cells touching two to four
foreign faces carry \emph{smaller} residuals.
\item \textbf{Cut orientation, not cut jaggedness alone, sets the magnitude.} The hierarchy
in Table~\ref{tab:phenomenon} is orientation-ordered: \(x\)-normal planar slabs 0.00054\%,
\(y\)-normal planar slabs 0.47\%, \texttt{scotch}'s jagged mixed-orientation boundary 8.95\%
--- and the worst cross-residual entries sit on \(y\)-normal processor faces.
\item \textbf{The same instrument on the clean arm is five thousand times quieter.} Applied
to the \texttt{simple} 4x1x1 \(\psi\), the serial operator maxes at \textbf{0.008439} on that
arm's own interface cells (9 of its top 10 entries sit on them) --- \(5{,}006\times\) below
\texttt{scotch}'s 42.25. Had \texttt{simple}'s residual also been huge, the test would have
proven nothing.
\end{itemize}

\paragraph{The hanging-node hypothesis, refuted backwards.} The natural first guess on a
refinement-interface mesh is that partition cuts crossing hanging nodes are the trigger. The
supervisor sweep re-classified all 7{,}843 internal faces itself, from
\artifact{owner}/\artifact{neighbour}/\artifact{cellLevel} and the archived
\artifact{cellDecomposition} maps: 456 refinement-interface faces, of which \texttt{scotch}
cuts \textbf{4} (0.88\%) and \texttt{simple} 4x1x1 cuts \textbf{68} (14.91\%).
\emph{The decomposition that cuts seventeen times more refinement interfaces is the accurate
one.} The hypothesis is refuted, not merely unconfirmed.

\subsection{The mechanism, named --- and what is not claimed}

\paragraph{Named.} Under decomposition, DAFoam v5's reverse-mode AD product
\((\partial R/\partial W)^{\mathsf T} v\) --- the global-tape shell operator the adjoint KSP
iterates (\artifact{initializeGlobalADTape4dRdWT} / \artifact{dRdWTMatVecMultFunction},
\artifact{DASolver.C:1364ff}) and the \artifact{calcJacTVecProduct} API that reverses the same
recorded computation --- differs from the true transposed Jacobian of the discrete residual
at partition-interface cells, by amounts that depend on the cut's shape and orientation.

The two parallel AD paths sit \emph{together} on the wrong side: they agree with each other
to \(1.2\times10^{-3}\) of \(\lVert b\rVert\) while both sit \(3.3\times10^{2}\) of
\(\lVert b\rVert\) from the serially evaluated truth. The defect is therefore common to the
recorded reverse computation, not to one call site. GMRES then solves the wrong system
exactly; the adjoint inherits \(O(1)\) error along the directions the wrong operator
mislabels (hence the \(16.5\times\) norm inflation); and the gradient contraction
\(\psi^{\mathsf T}\,\partial R/\partial X_v\) delivers the 8.95\%. Every observed symptom
follows: converged wrong answer, tolerance invariance, decomposition dependence,
primal/FD/RHS invariance, and the near-invariance of the lab's conformal-mesh cases.

\paragraph{Not claimed.} The defective source line. The candidate surface is the reverse-AD
handling of inter-processor halo exchange inside the recorded residual evaluation --- the
CoDiPack tape over OpenFOAM processor-boundary updates --- and pinning the line requires an
instrumented rebuild of \artifact{libDASolver.so}. What \emph{is} pinned: the subsystem, the
spatial signature (interface-cell \(x\)-momentum rows), the orientation dependence, and the
discriminating instrument that any candidate fix must satisfy.

\paragraph{A continuum, not a binary.} The FD-exact \texttt{simple} 4x1x1 \(\psi\) still
leaves \(9.4\times10^{-2}\) of \(\lVert b\rVert\) under the serial operator --- roughly
\(800\times\) the np=1 floor --- while its gradient is correct to 0.00054\%. Every np=4
operator tested differs measurably from serial; \texttt{scotch}'s jagged cut is the
catastrophic point on a continuum, not a separate species.

Three facts fall straight out of Table~\ref{tab:papers}.

\begin{enumerate}
\item \textbf{No paper ever varies the decomposition of anything.} Decomposition is not an
experimental axis anywhere in the corpus --- not at fixed process count, not across process
counts. The two papers that verify DAFoam's v1 operator in (implied) parallel never state
what the decomposition was.
\item \textbf{The operator our defect lives in has exactly one published accuracy
measurement, and it is serial.} The survey states the reason in its \S5.1 --- running on one
CPU core ``allows us to isolate the impact of parallel communication on the performance'' ---
and confirms the gap in its conclusions: \emph{``We do not have scalability data for the
Jacobian-free (operator overloading) and the full-code AD (operator overloading) options
because we run the adjoint computation only in serial in the ADODG Case 3 (Sec. 5.1).''}
\item \textbf{No verification anywhere combines a refinement-interface mesh with a stated
graph partitioning.} The one snappy-mesh verification --- C\&F 2018's Ahmed body, our
defect's own geometry family --- is of the v1 explicitly FD-assembled Jacobian, an
architecture in which a tape-recording defect cannot exist, at an unstated decomposition.
\end{enumerate}

\paragraph{A published claim, corrected against ourselves.} An earlier draft of our own
upstream report asserted that ``the toolchain's journal paper reports average adjoint
derivative error under 0.1\% at up to 1536 cores'' and that our measurement therefore
contradicts a peer-reviewed number. Reading the paper in full showed that sentence to be
\emph{wrong twice}. The abstract joins two disjoint experiments with an ``and'': the 1536
cores is a runtime-only table on a 10.1M-cell structured mesh; the \(<\)0.1\% is a separate
\(\sim\)103k-cell accuracy study at an unstated processor count. \textbf{No accuracy number at
any stated core count exists in that paper.} And both \(<\)0.1\% figures attach to the v1
explicit-FD-Jacobian architecture --- the same paper pairs them with ``Implementing the
Jacobian-free approach in DAFoam \ldots\ will be conducted in the future work.'' The 0.1\%
scale is the FD-partials error floor, not a parallel-consistency scale.

This \emph{strengthens} the case rather than weakening it: the report does not contradict a
published measurement, it fills a hole the survey's own conclusions declare.

\paragraph{No archival method paper covers the shipped architecture.} The DAFoam
publications page lists no framework paper after 2020; the \artifact{mdolab/dafoam} README's
citation section names exactly the two He et al.\ papers, tied to no version; a JOSS search
finds nothing; Zenodo records 15636000 (v4.0.2) and 20045081 (v5.0.0) are software deposits,
not papers. The v2.2 release note that shipped the Jacobian-free adjoint cites no paper for
it either. \emph{The v4/v5 rewrite we measured has no archival method paper at all}; the
citation trail for the shipped matrix-free adjoint ends at papers describing other
architectures.

\paragraph{Was the defect class disclosed anywhere?} Two quotes were fetched for exactly this
question, and neither is a tape caveat. C\&F 2018 \S2.9 names interprocessor boundary-patch
state updates as \emph{``essential for accurately computing the adjoint derivative''} --- for
the v1 FD path, where they are handled by executing
\artifact{U.correctBoundaryConditions()} per perturbation. The v5 tape must \emph{record}
that same coupling, and its interface-cell rows are exactly where our cross-residual
concentrates. PAS 2019 \S A.4 acknowledges that \emph{``some code structures remain a
challenge to differentiate, including pointers and MPI calls''}, and that ADflow's parallel
derivative correctness rests on manual assembly using properties ``that the AD code cannot,
in general, safely assume'' --- a statement about AD-across-MPI as a hazard class, made about
ADflow's development choices.

No paper states a halo-exchange tape caveat or a partition-consistency assumption for
DAFoam's operator-overloading path. There is no sentence a maintainer could point to as prior
disclosure. What the quotes support is gentler and more useful: \textbf{the defect sits in a
subsystem whose verification the papers explicitly scoped out, in a region their own earlier
work flagged as accuracy-critical.}

\section{The IDWarp rotation guard}
\label{sec:idwarp}
%======================================================================

This defect is independent of Section~\ref{sec:decomp} --- it is geometric, serial, and lives
in a different repository --- but it was found in the same arc, it contaminated the same
gradients, and it had to be removed before the decomposition measurements could be trusted.
It is also the cleanest of the three: root cause named to a line, confirmed by repair.

\subsection{The line}

IDWarp \textbf{2.6.2} is the exact version in \artifact{dafoam/opt-packages:latest}
(image digest
\artifact{sha256:9d45679d55fd\allowbreak 47f5ca7afd99\allowbreak cabb86c7c272\allowbreak 9cf2acf34c43\allowbreak 8eb33af5290f07fc}); the
installed \artifact{idwarp/*.py} files are md5-identical to the \texttt{v2.6.2} tag of
\artifact{https://github.com/mdolab/idwarp}, tag commit \commit{647fd8fc}.

The warp displaces each volume node by an inverse-distance weighted sum in which the weights
\(W_i\) are \emph{constant} with respect to the surface coordinates; all the surface
dependence lives in a rotation matrix \(M_i\) and a displacement \(b_i\), with
\(S_i = M_i\cdot(r - X_{u0,i}) + (X_{u,i} - r)\). \textbf{The rotation acts on the lever arm
from the surface node to the volume node.} \(M_i\) is built at
\artifact{src/modules/kd\_tree.F90:1639--1640} as \(R(n_0 \rightarrow n)\), by:

\begin{lstlisting}[language=Fortran]
real(kind=realType), parameter :: tol = 1.4901161193847656e-08   ! line 44 (= sqrt(eps))
call cross_product_3d(v1, v2, axis)
call getMag(axis, axisMag)
! When axisMag is less that sqrt(eps), the acos 'arg' value will be
! exactly one which will give a nan in complex mode.
if (axisMag < tol) then                                          ! line 58   <<< HERE
    angle = zero
    axis  = zero
    axis(1) = one
else
    axis = axis / axisMag
    vv1 = v1 / magv1 ;  vv2 = v2 / magv2
    arg   = min(one, vv1(1)*vv2(1) + vv1(2)*vv2(2) + vv1(3)*vv2(3))
    angle = acos(arg)
end if
Mi = Mi + sin(angle) * A + (one - cos(angle)) * C                ! Rodrigues
\end{lstlisting}

The map \(M_i(n_0, n)\) is perfectly smooth at \(n = n_0\), with the finite, non-zero
derivative \(\mathrm{d}M_i = [n_0\times \mathrm{d}n]_\times\). But \emph{this
parameterisation} --- normalise the cross product, take \texttt{acos} of the dot product,
apply Rodrigues --- has a removable coordinate singularity there: \texttt{axis} is \(0/0\)
and \(\mathrm{d}(\arccos)/\mathrm{d}(\texttt{arg}) \rightarrow \infty\). The guard exists to
stop that becoming a NaN, and the source comment says so. It replaces the singularity with
\texttt{angle = 0}.

\paragraph{What Tapenade does with the guard.} In the generated reverse file
\artifact{src/adjoint/outputReverse/vectorUtils\_b.f90:123--128}, when the guard branch was
taken the reverse sweep \emph{zeroes every adjoint on the path back to} \texttt{v2}; the
subsequent \texttt{GETMAG\_B} and \texttt{CROSS\_PRODUCT\_3D\_B} calls therefore propagate
exactly zero, and \(\mathrm{d}M_i/\mathrm{d}(\texttt{normals}) = 0\) exactly. Tapenade is not
at fault: it differentiated the branch that was taken. The defect is that the branch taken is
a \emph{constant} where the true function has a non-zero first-order term.

\paragraph{The guard fires with certainty at every gradient evaluation.} \artifact{getMag}
regularises with \(+10^{-30}\) under the square root. At an undeformed baseline
\texttt{normals == normals0} bit-for-bit (same code, same inputs), so
\(\texttt{axis} = n_0\times n = 0\) and \(\texttt{axisMag} = \sqrt{10^{-30}} = 10^{-15} <
1.4901\times10^{-8}\). \textbf{Branch 0, guaranteed, at every non-corner surface node.} A
\artifact{check\_totals}, a first design iteration, and every gradient probe are evaluated at
exactly that state. The finite difference, meanwhile, perturbs the surface by \(h\) and tilts
adjacent faces by \(\theta\sim h/L\), far above the threshold --- so the FD sees a
first-order rotation term the AD has set identically to zero. \emph{That difference is the
gap.}

On the three shear cases the deformation genuinely rotates normals, the guard does
\emph{not} fire, the AD \emph{does} change when rotations are switched off --- and with
rotations \textbf{on} those cases are clean at \(10^{-5}\%\) to \(10^{-6}\%\).
\textbf{When the rotation branch is live, \artifact{warpDeriv} is correct.} The catastrophic
failure is confined to \(n \approx n_0\). This is a sharper and more falsifiable statement
than the one we started with, and it is the correct one.

\paragraph{The capstone that could have refuted it.} If the failure is the degenerate branch
specifically, then moving a case off its undeformed baseline should make the guard stop
firing, at which point \artifact{warpDeriv} must become sensitive to \texttt{useRotations}
and get dramatically more accurate. With all 27 shape design variables pre-set to 0.02 on the
U-bend case, the two sign flips vanish and the worst error falls from 207.0\% to 8.2\% with
nothing else changed --- and the fingerprint confirms the branch is now live:
\(\lVert dX_s\rVert\) is \(1.495168856286067\times10^{3}\) at the undeformed baseline whether
rotations are on or off (\emph{identical} --- branch dead), and
\(1.566420804338303\times10^{3}\) vs \(1.495168856286067\times10^{3}\) pre-deformed
(\emph{differs} --- branch live). Had the mechanism been ``rotations are mis-differentiated'',
this experiment would have failed flatly.

\subsection{Why upstream's CI cannot see it}

Four independent mechanisms, each verified against primary source.

\begin{enumerate}
\item \textbf{The assertion is missing.} \artifact{tests/test\_USMesh.py:86} calls
\artifact{mesh.verifyWarpDeriv(...)} and \emph{discards the result}. Nothing is asserted on
it --- which is exactly what upstream issue \#57 says.
\item \textbf{The only thing asserted is blind by construction.} The regression check is
\texttt{handler.root\_add\_val("... Sum of dxs:", val, tol=1e-8)}. Across five meshes the
rotation term contributes \emph{exactly zero} to that sum (identical to 0--1 ulp) while
changing \(\lVert dX_s\rVert\) by factors of 5 to 34. Five for five, upstream's check cannot
detect a change that alters the derivative vector by a factor of 34.
\item \textbf{A dot-product test cannot detect it either, and is not run.}
\artifact{examples/structured/dotprod.py} lives in \artifact{examples/}, not
\artifact{tests/}. And a dot-product test only proves forward-AD and reverse-AD are mutual
transposes: if both linearise a \emph{different} function than the warp, they do so
identically and the dot product is still zero.
\item \textbf{The verification tool defaults to a random seed.}
\artifact{UnstructuredMesh.py:460}: \texttt{def verifyWarpDeriv(self, dXv=None, ...,
randomSeed=314)}. A random direction contracts the error against a direction it barely
overlaps (0.32--1.30\% where the real objective seed reads 207\%, flipped).
\end{enumerate}

\paragraph{Not a documented approximation.} No documentation, release note, docstring, or
source comment qualifies \artifact{warpDeriv} as approximate. The docs say only ``Compute the
warping derivative (dXv/dXs\textasciicircum T)*Vec''; the \artifact{warpDeriv.F90} header says
only ``Compute the following matrix vector product: dXv/dXs\textasciicircum T * Xvbar''. Both
present it as the exact transpose Jacobian. \emph{One disclosed gap:} the primary IDWarp
reference (Secco, Kenway, He, Mader, Martins, \emph{AIAA J.}\ 59(4):1151--1168, 2021,
doi:10.2514/1.J059491) could not be retrieved --- five umich URLs return 403 including the
authors' own bibliography link, and OpenAlex (\texttt{is\_oa: false}, \texttt{oa\_status:
"closed"}) and Semantic Scholar independently report no open copy. No claim is made about
what that paper says, and the ``undocumented'' characterisation rests on code, docs and
release notes only.

\subsection{The upstream issue this answers}

\artifact{mdolab/idwarp\#57}, ``\texttt{inflate\_cube} test appears to fail'', opened
2021-07-14, labelled \texttt{bug}, \textbf{open, zero comments, five years untouched}. Its
timeline contains exactly one event: the label, applied 8 seconds after creation. Its author
wrote: \emph{``the output from this test appears to show large errors in some of the
derivative terms. However, these error values are not actually used as a unit test and so the
entire test suite still passes''}, and \emph{``Given how weird the FD values are for the two
terms with big errors, it may be that the issue is in those rather than the AD values, but
it's hard to see how that could be the case.''}

We reproduced the issue exactly --- IDWarp alone, no DAFoam, no OpenFOAM, no CFD, using
IDWarp's own test mesh, options, displacement and verification routine --- and answered its
open question adversarially. A step-size study on the two failing degrees of freedom gives FD
values stable to six significant figures across three decades (\(h = 10^{-4}\) to
\(10^{-6}\)), with subtractive roundoff appearing only at \(10^{-8}\).
\textbf{The finite difference is converged; the AD is the wrong one.}

Why degrees of freedom 0 and 3 and not 1, 2, 4, 5: \texttt{inflate\_cube} scales an
axis-aligned block by (1.1, 1.2, 1.3), which leaves every face normal \emph{exactly}
unchanged, so the guard fires even at the deformed state. Perturbing a node \emph{along} its
face normal tilts adjacent faces at first order and switches the rotation term on; perturbing
it \emph{in} the face plane does not. That is a clean instance of our own predicted-clean
control, appearing unbidden inside upstream's five-year-old data.

\subsection{The patch, and what it proves}

The derivation was written \emph{before} the code, and every sign was checked by a controlled
experiment with a hand-computed known answer before any system-level run. With
\(u_1 = v_1/\lvert v_1\rvert\), \(u_2 = v_2/\lvert v_2\rvert\): \(\sin\theta\,[k]_\times =
[u_1\times u_2]_\times\) exactly, and \((1-\cos\theta)[k]_\times^2 = O(\theta^2)\), so
\(M_i = I + [u_1\times u_2]_\times + O(\theta^2)\) and, at \(u_2 = u_1\),

\[
\mathrm{d}M_i = [w]_\times,\quad w = \frac{v_1\times \mathrm{d}v_2}{\lvert v_1\rvert\,\lvert v_2\rvert}
\qquad\text{(forward)}
\]
\[
v_{2b} \mathrel{+}= \frac{\operatorname{axial}(m_{ib} - m_{ib}^{\mathsf T})\times v_1}{\lvert v_1\rvert\,\lvert v_2\rvert}
\qquad\text{(reverse, by the cyclic triple product)}
\]

\(\lvert v_1\rvert\) and \(\lvert v_2\rvert\) are already recomputed in the reverse routine's
forward sweep and are in scope inside the branch. \textbf{The whole fix is four lines of
assignment in the \texttt{branch .EQ. 0} block}, replacing nothing: the three zeroed
intermediates stay zeroed, because the dummy-axis path they belong to really does carry zero;
the patch adds the term that path lost. The diff is 2 files, +44 lines, all in
\artifact{src/adjoint/output\{Reverse,Forward\}/vectorUtils\_\{b,d\}.f90}.

\paragraph{Two limits, stated plainly.} First, \textbf{retuning the tolerance cannot fix
this.} \texttt{tol} is exactly \(\sqrt{\varepsilon}\), but the \texttt{acos(min(1, v1.v2))}
construction is numerically flat on its own out to \(\sqrt{2\varepsilon} =
2.1073\times10^{-8}\) rad: \(1-v_1\!\cdot\!v_2 = \theta^2/2\) drops below \(\varepsilon\),
\texttt{arg} rounds to bit-exact 1.0, and \texttt{acos(1.0)} is exactly 0, guard or no guard.
Measured at \(\theta = 10^{-8}\): \texttt{arg} bit-exactly 1.0, \(1-\texttt{arg}\) bit-exactly
0.0. \emph{The first thing a maintainer will reach for is foreclosed.} Second, \textbf{the
AD's zero is the exact derivative of the implemented function at that point.} The guard makes
the warp genuinely flat in a ball of angular radius \(\sim\!1.5\times10^{-8}\) rad, and a
finite difference taken entirely inside that ball returns exactly 0.0, agreeing with the AD to
every digit. Tapenade is correct about the code as written. The defect is precisely that
\artifact{warpDeriv} returns \emph{the derivative of a flat spot that no optimizer can
traverse and no finite difference can resolve} --- reaching it needs
\(h < 1.5\times10^{-8}L\), and the step study already shows roundoff destroying the FD at
\(h = 10^{-8}\). Any filing should pre-empt the response ``the code is differentiable and your
step is too coarse.''

\subsection{The second regime, and the fix that covers both}

Away from the baseline, with \texttt{axisMag} just above \texttt{tol}, the guard does not fire
and the derivative \emph{is} computed --- but through an \texttt{acos} whose argument has lost
its information to cancellation. This regime is real, measured on ONERA M6 at \(\sim\)1.26\%,
and \textbf{survives the patch, exactly as predicted} before the acceptance runs. Its cause
was \emph{tested} rather than asserted, by repairing each candidate line in isolation:

The dominant term is \texttt{angle = acos(arg)} in the \emph{primal}: \(\texttt{arg} = 1 -
\theta^2/2\) loses the information at \(\theta\sim\sqrt{\varepsilon}\) before \texttt{acos} is
ever called, and the reverse inherits it. Neither line is sufficient alone and the two do not
add. Only \texttt{angle = atan2(axisMag/(magv1*magv2), arg)} \emph{together with}
\(\sqrt{1-\texttt{arg}^2} \rightarrow \texttt{axisMag}/(\texttt{magv1}\cdot\texttt{magv2})\)
removes the regime --- and the substitute is free, because \texttt{axisMag} is already
computed two lines earlier in the primal.

\textbf{The recommended upstream fix is neither of our patches but the reparameterisation}
\(R = I + [v]_\times + [v]_\times^2/(1+c)\) with \(v = a\times b\), \(c = a\cdot b\): a
polynomial in \(v\) with the smooth coefficient \(1/(1+c)\), giving \(I\) with the correct
derivative at \(a = b\), needing no threshold, and unable to NaN except at exact reversal ---
a genuine singularity of the problem rather than of the parameterisation. It is measured here
at \(6.3\times10^{-13}\) to \(2.2\times10^{-12}\) across every angle tested \emph{including
inside the guard ball}, where every \texttt{acos}-based variant reads exactly 1.0. It is the
only single change that covers both regimes.

Two caveats attach. A regime-2 repair \textbf{cannot} be primal-bit-identical --- it changes
\texttt{angle} in the forward warp (\(M_i\) moves by 1 ulp at \(\theta = 1\)) --- so any such
patch must be re-graded on the primal as well as on the gradient. And our shipped patch is a
\emph{proof of concept on the generated file}: upstream should fix the primal's
parameterisation and regenerate, not merge a hand-edit of Tapenade output.

\subsection{Workaround, with its price named}

\texttt{useRotations: False} in \artifact{meshOptions} restores gradient consistency to
roundoff on all evidence here --- it makes the warp exactly linear in the surface
coordinates. It is not free: upstream documents rotation interpolation as what ``will help
preserve boundary layer orthogonality'' under large orientation changes, so mesh quality
under large deformation is the price. \textbf{That trade has not been measured by this lab},
and no optimisation has been re-run under it. Recommending it as a default would be premature.

\subsection{The wall}

On a 21{,}000-cell curved-backward-facing-step (CBFS) field-inversion case, the DAFoam
adjoint linear solve fails at iteration 0 with \texttt{PetscConvergedReason: -9}
(\texttt{DIVERGED\_NANORINF}) and printed iteration-0 residual
\(7.091590452305\times10^{-4}\). It fails identically under all five available
\artifact{jacMatReOrdering} values --- two produce \(-9\), three produce \(-3\) flat
stagnation, none converges --- and the printed initial residual is identical to 13 digits
across all of them, which is the tell that the failure is in the factorization, not the
Krylov space.

\subsection{The offline reproducer, which made every candidate a ten-second experiment}

The dumped CBFS system (\artifact{dRdWTPC}, \(210{,}592^2\), nnz 13{,}710{,}468, plus the
right-hand side whose norm matches the printed iteration-0 residual to 13 digits) was solved
with a petsc4py harness that replicates \artifact{DALinearEqn::createMLRKSP}'s call sequence
\emph{in order} --- \texttt{KSPSetFromOptions} first, hard-coded GMRES/ASM/sub-ILU settings
second --- under \texttt{mpirun -np 4}, the real layout:

\end{lstlisting}

Bit-for-bit DAFoam's failure --- same reason, same iteration count, same residual --- with
\texttt{PCView} confirming full parity (ILU fill 1, ordering rcm, shift \texttt{NONZERO},
pivot-in-blocks, zeropivot 2.22e-14).

\subsection{Where the remedy comes from, and why it is not exotic}

Switching failing ILU sub-blocks to LU is the PETSc developers' own canonical escalation, not
an invention of this lab. From the petsc-users archive, verbatim: \emph{``The default
preconditioner with ILU(0) on each process is not appropriate for your problem and is
producing overflow. Try -sub\_pc\_type lu and see if that produces a different result''}
(Barry Smith, \texttt{msg24474}, 2015-03-26); and \texttt{msg26973} (Hong, 2015-10-27)
demonstrates on a zero-diagonal system that ILU with any shift ``does not converge'' while
\texttt{-sub\_pc\_type lu -sub\_pc\_factor\_shift\_type nonzero} converges in 24 iterations.
The PETSc FAQ states, verbatim: \emph{``The convergence of many of the preconditioners in
PETSc including the default parallel preconditioner block Jacobi depends on the number of
processes.''}

The complete upstream DAFoam remedy ladder for a non-converging adjoint, assembled from every
place it is stated (the run-script guide, the FAQ, the doxygen \texttt{DAOPTION} page, and the
live discussion threads) is: \texttt{renumberMesh -overwrite}; \texttt{pcFillLevel} 1
\(\rightarrow\) 2; \texttt{jacMatReOrdering} rcm \(\rightarrow\) nd/natural;
\texttt{gmresRestart}/\texttt{gmresMaxIters} up; \texttt{asmOverlap} up; upwind schemes;
(since 2025-12) kahip decomposition; and \texttt{transonicPCOption} for transonic cases.
\textbf{Nothing in that ladder changes the sub-PC type; the ILU choice itself is never
questioned upstream}, and no upstream doc, issue or discussion mentions ILU singularity, zero
pivots, or a direct/sub-direct factorization at all --- under 8 targeted searches plus 4
doc-page reads. Meanwhile \artifact{mdolab/dafoam} discussion \#1002, converted to issue
\#1011 on 2026-07-29 and still open, shows users exhausting the documented ladder on
\emph{official tutorials} and stalling: the failure mode this switch was built for is live
upstream today.

\paragraph{The shape of a filing.} An upstream pull request exposing the sub-PC type as an
\artifact{adjEqnOption} key --- default \texttt{ilu}, behaviour unchanged --- would be novel,
is one option plumb, and is backed by both a measured unblock and named-PETSc-developer
precedent. Our local implementation is one hunk at \artifact{DALinearEqn.C:266}
(\artifact{demo-output/website/dafoam/subpclu\_patch/DALinearEqn\_subpclu.patch},
\commit{1cd44c04}); its default-off behaviour was verified by re-running the unpatched
configuration on the patched image and reproducing the \(-9\) at iteration 0 with all 13
residual digits intact.

\subsection{What the change does \emph{not} fix}

On the NASA hump (51{,}626 cells, 51{,}626 \(\beta\) design variables) the same one-word
change moves the failure from catastrophic to honest, and no further. The
\texttt{-9} is gone --- the complete-LU factorization of blocks ILU cannot factor completes,
and GMRES iterates with a monotonically descending residual, \(1.094138002900\) at iteration 0
to \(0.9544468674795\) at iteration 900 --- but it descends slowly, 12.8\% in 900 iterations
(accelerating: 0.75\%, 1.1\%, 1.2\%, 1.6\% per successive hundred) and far from the target.
The run was stopped deliberately at roughly iteration 900 when host available memory fell from
30.5~GB to a low-water \textbf{1.62~GB} under about 19~GB of LU factors plus a still-filling
2000-vector restart space, on a shared box.

Stated for whoever picks this up: \textbf{the hump blocker is no longer the singular
factorization --- it is Krylov convergence rate against a memory envelope}, which is a
different and honestly-named problem.

\section{Methods: adversarial verification as practice}
\label{sec:methods}
%======================================================================

Every headline claim in this document has survived an independent adversarial sweep. That
phrase is used precisely, and this section says what it buys, because a reader assessing
three unfiled defect claims is entitled to know what standard they were held to.

\subsection{What a supervisor sweep is}

A verification agent is dispatched with the posture that \textbf{the claim is wrong until it
survives attack}. It does not review the record; it re-derives the record. Concretely, across
the four sweeps behind this document:

\begin{itemize}
\item \textbf{Independent instruments, not re-runs of the lab's scripts.} The mechanism sweep
rebuilt the processor-to-serial permutation from scratch with its own parsers, from
\artifact{cellProcAddressing}/\artifact{faceProcAddressing} and the \artifact{AdjointIndexing}
dumps, then compared against the stored map: identical bit-for-bit in target and sign. The
rotation sweep wrote its own NumPy check of the corrected derivative (250 draws, against
Richardson central differences of the singularity-free reference) and its own DAFoam driver
that wraps \artifact{idwarp.USMesh.warpDeriv} itself rather than the lab's hook.
\item \textbf{A new validation channel the original never used.} The AdjointIndexing dumps
carry cell and face centre coordinates; mapping np=4 coordinates onto np=1 coordinates gives
max deviation \textbf{0.0} over all 26{,}149 and 26{,}227 entries, validating every entry of
the permutation exactly and independently of any solved field.
\item \textbf{Re-measurement from scratch, in the container.} One cell of the phenomenon table
(np=2, patched) was re-run with the sweep's own driver, own staging, own container
invocation: analytic, FD, absolute error, relative error, baseline \(C_D\) and GMRES iteration
count \emph{all identical to every printed digit}, and carrying the provenance stamp the
archived run lacked. Cost: 86~s wall, 2.9 solver core-min.
\item \textbf{A point the lab did not choose.} The conditioning sweep verified a
finite-difference cell (6490) the lab never published, at a different rank band, and got
0.0211\% --- tighter than any published cell. A wrong indexing, a stale gradient file, or a
lucky triple would not survive that.
\item \textbf{Cold reproduction of the control, not just the treatment.} The env-off
regression was re-run cold by the sweep, on a fresh case copy: reason, iteration count, and
all 13 residual digits matched independently of anything the original session wrote.
\item \textbf{The ledger is audited to the second.} Billed walls were reconciled against log
mtimes and internal timings --- e.g.\ five offline runs plus a 600~s kill summing to 693.04~s
against 693 billed; a memory trace whose first and last samples bracket 816~s against 819
billed; nine finite-difference runs whose per-run walls sum to \emph{exactly} 642.
\end{itemize}

\subsection{The lessons this arc produced}

The method itself is on the record, as numbered lessons in \artifact{LESSONS.md}:

\begin{itemize}
\item \textbf{L-29.} A guard that replaces a removable singularity with a constant
differentiates to a hard zero --- at exactly the point every gradient evaluation uses. Audit
every such guard on a differentiated path; require the guarded branch to carry the analytic
limit, or reparameterise so no guard is needed. And when \emph{testing} derivative code,
evaluate at the degenerate/baseline point deliberately and seed with the real objective
direction.
\item \textbf{L-30.} A gate whose threshold lies between two constraint values reports the
constraint, not the quantity. Before gating on a reported extremum, find out whether the tool
was \emph{told} that number.
\item \textbf{L-31.} A verification instrument must itself be verified at the component it
condemns. When an analytic derivative disagrees with a finite difference, re-measure the
finite difference by an independent path --- with a neighbouring component as a control ---
before attributing the gap to the derivative.
\item \textbf{L-32.} When a verdict moves, the case's own record must move first; satellites
are not the record.
\item \textbf{L-33.} A correction trained inside a gated regime rebuilds the gate's own
failure at the regime's floor.
\item \textbf{L-34.} ``Unreachable at runtime'' is a claim about the deployed object, not
about one call site. Deploy a probe that prints the final object state (for PETSc,
\texttt{PCView} on the sub-PC after setup) before declaring a configuration layer unreachable.
\item \textbf{L-35.} \emph{A converged Krylov solve certifies the operator it was given, not
the operator you meant.} When an iterative solve converges cleanly and the downstream answer
is still wrong, stop tuning the solve and test the operator: apply the converged solution
under an independently evaluated instance of the operator --- serial where the suspect is
parallel, assembled where the suspect is matrix-free --- and compare the residual to that
instance's own floor. It is a mat-vec, not a solve: seconds, not core-minutes. Two footnotes:
map vectors across decompositions with the integer addressing files (sign on flipped faces),
never coordinate matching, and validate the map on the primal state first; and diff operator
\emph{actions} on mapped vectors, never operator \emph{entries}.
\end{itemize}

\subsection{Varying the decomposition without falling into the trap}

Editing \artifact{system/decomposeParDict} directly is silently ineffective: \artifact{pyDAFoam}
regenerates it. Set the daOption instead, and \emph{read the decomposition back out of the
log}:

\begin{lstlisting}[language=Python]
daOptions = {
    # ...
    "decomposeParDict": {"method": "simple", "simpleCoeffs": {"n": [4, 1, 1]}},
    # default when unset is {"method": "scotch"} -- pyDAFoam.py:590-591
}
\end{lstlisting}
\begin{lstlisting}[language=bash]
# Verify the edit took effect -- this line is the check that catches the trap:
grep "Decomposition method" run.log
#   Decomposition method scotch [4] (region region0)
#   Decomposition method simple [4] (region region0)
\end{lstlisting}

\subsection{The cross-residual protocol}

Pure DAFoam public API; no rebuild required. This is the instrument any candidate fix must
satisfy.

\begin{lstlisting}[language=Python]
# 1. Per decomposition: run the primal + adjoint, then dump
#      psi   = DAFoamSolver.psi
#      state = the converged primal state vector
#      b     = dFdW (the adjoint RHS)
#    with, in daOptions:
#      "writeJacobians": ["adjointIndexing"]
#    which emits AdjointIndexing_<rank>_of_<n>.txt (indices + cell/face centres).

# 2. Build the exact integer permutation to serial ordering from
#      processor*/constant/polyMesh/cellProcAddressing
#      processor*/constant/polyMesh/faceProcAddressing   (sign => flipped face)
#    NEVER by coordinate matching. Validate it on the PRIMAL state first:
#    duplicated processor-face phi copies must agree to machine precision
#    (measured here: 2.7e-15). The AdjointIndexing centres give a second,
#    exact channel: max |dxyz| must be 0.0.

# 3. Evaluate the true residual under the SERIAL operator, matrix-free:
#      r = solverAD.calcJacTVecProduct(state -> residual)  applied to mapped psi
#    SIGN CONVENTION: OpenMDAO seeds -dF/dW, so the system is  A^T psi = -b.
#    An instrument computing (A^T psi - b) prints a degenerate ratio of exactly
#    2.0 for its own-operator control -- that is the tell that the sign is wrong.
#    Correct offline as res + 2b, or fix the instrument.

# 4. Judge against the SERIAL operator's own floor, not against zero:
#      np=1 control ......... 1.14e-04 of ||b||   <- the floor
#      np=4 simple 4x1x1 .... 9.37e-02
#      np=4 scotch .......... 3.288e+02           <- the defect
\end{lstlisting}

Lab scripts implementing this: \artifact{W4-a4-discriminators/runScript\_w4.py} (tasks
\artifact{w4\_dump}, \artifact{w4\_crossres}, \artifact{w4\_crossres2}),
\artifact{build\_maps.py}, \artifact{analyze\_mats.py}.

\item \textbf{D3, the hump.} Krylov convergence rate against a memory envelope. A prepared
configuration wrapping the exact sub-solve in Richardson with a capped restart is staged but
unrun.
\end{enumerate}
