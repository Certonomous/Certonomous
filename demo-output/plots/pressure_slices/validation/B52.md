# B-52 surface-pressure field: triple-check before it stays on camera

Scope: the painted B-52 surface pressure served to the GUI
(`mission-output/geometry-study/b52_field.json`), the wireframe display mesh
behind it, and the pressure the website slice was rendered from. Everything
below is read from the solved cases' own `foamToVTK` output.

Three things changed under this picture since the round-2 screenshot
(`demo-output/acts/round2/b52/03-cp-painted.png`, 2026-07-23, "15,660 faces",
Cd 0.0464, 193,815 cells, skew 5.06): the mesh was rebuilt under the
boundary-skewness gate, the geometry was rescaled from a generic 50 m length
to the published 48.5 m, and the GUI gained a display-only orphan-island
filter. Each is sized separately below.

## Verdict

**PASS.** Every physics invariant holds with margin and none is violated
anywhere on the body. The served JSON is the solver's own field to the last
digit. The orphan-island filter is proved to be display-only: the surviving
faces keep their own values and their own corner positions exactly.

The stated limit — not a failure — is that the nose stagnation peak reads
Cp 0.718 rather than approaching 1, because the faces carrying it are 0.41 m
across (0.9% of body length) and the peak is under-resolved. The pre-remesh
mesh reads 0.727 on the same measure, so this is the mesh scale, not the
remesh and not the rescale.

## 1. Physics invariants (all pass)

- **p_inf.** 0.0098 m2/s2, median cell pressure beyond 3 body lengths radius
  (64,326 cells). 2e-6 of q — effectively zero.
- **Stagnation bound.** p_inf + U^2/2 = 5,000.01 m2/s2. Max wall p/rho =
  3,590.8, Cp 0.718 <= 1. **Zero faces above the bound**, anywhere on the
  body. Minimum Cp -1.048.
- **Why the peak is 0.718 and not ~1.** The faces carrying the top 0.5% of
  wall pressure are a median 0.41 m across, 0.9% of the 48.5 m length; a
  boundary value at that stand-off from a rounded radome cannot reach the
  stagnation value. The pre-remesh, pre-rescale case reads Cp 0.727 on the
  identical measure — the same shortfall, so it belongs to the mesh scale
  rather than to either change. This under-shoots, which is the conservative
  direction, and it is the same effect already declared for the NACA sections
  in `VALIDATION.md`.
- **Stagnation sits on forward-facing surfaces.** Of the top 0.5% (40 faces,
  threshold Cp 0.578), **100%** have a positive flow-axis normal component
  (mean 0.544, median 0.692). Location: 52.5% nose/cockpit, 30.0% wings and
  engine pods, 17.5% mid-fuselage, 0% tail fin. Nose and leading edges, as
  required.
- **Suction sits on acceleration zones.** The bottom 0.5% (38 faces,
  threshold Cp -0.614) is 76.3% on the wings and engine pods, 13.2%
  nose/cockpit shoulder, 10.5% mid-fuselage, 0% tail fin. **None** of them is
  forward-facing (frac_forward 0.0, mean flow-axis component -0.570): the
  suction set and the stagnation set are cleanly opposite in orientation,
  which is the discriminating check.
- **Far-field decay.** Mean |Cp| on upstream spherical shells: 0.00159 at
  1 L, 0.000226 at 2 L, 0.000086 at 3 L (6,949 / 1,689 / 3,620 cells). A
  factor 7 per body length, decaying to 1e-4 of q.

## 2. Old vs new: physics, rescale, rendering

### Remesh + rescale physics: small and measured

Both cases were reduced to area-weighted mean surface Cp in 41 bins of
normalised length z/L, so the 3% geometry rescale does not create a spurious
offset:

| | Value |
|---|---|
| RMS dCp over the 41 shared bins | **0.0052** |
| Max |dCp| | 0.0166, at z/L 0.67 |
| Area-weighted Cp percentiles, new | -0.431 / -0.161 / -0.080 / -0.006 / 0.330 (2/25/50/75/98) |
| Area-weighted Cp percentiles, old | -0.430 / -0.156 / -0.082 / -0.008 / 0.323 |
| Colour-window shift | **1.40% of the window span** |
| Cd | 0.0464 -> 0.0472, +1.72% |

### What the rescale alone is expected to do

The rescale is a real Reynolds shift, and a small one. Pressure coefficients
on a fixed shape are Reynolds-independent to first order; the friction
component follows roughly Re^(-1/7) in the turbulent flat-plate sense, so a
-3.0% Re shift predicts about **+0.44%** on skin friction. The measured total
Cd moved +1.72%, of which the Re effect accounts for a fraction — the
remainder is the remesh (skew 5.06 -> 3.91 changes exactly the boundary-face
interpolation the force integral reads). Both are small, both are in the
right direction, and neither is visible in the paint: the colour window moved
1.4% of its span.

### Rendering: no effect on this body

The painted B-52 is **not** decimated. Its single `body` patch triangulates
to 15,684 faces, below the 30,000-face threshold, so `_package_painted`
passes the values straight through and the 2026-07-25
decimation-correspondence fix (`b203327`) cannot have changed one pixel of
it. That is confirmed on the artifact rather than assumed: the round-2
screenshot caption reads "15,660 faces" — total equals shown then as well —
and the current field paints smoothly at neighbour-face correlation
**r = 0.952** over 23,447 shared-edge pairs. The pre-fix truncation paint
that speckled the decimated motorbike has no analogue here.

The 2nd/98th percentile colour clipping is likewise unchanged: the identical
index arithmetic is present in `_attach_field` at `7608e28` (2026-07-23),
before the round-2 screenshot.

Window (m2/s2): old case [-1846.96, 1095.15] -> new case [-1841.77, 1136.74].

## 3. Display integrity and the orphan-island filter

The filter in `control_room.html` (`dropOrphanIslands`) was mirrored step for
step in Python — same 1e-5-of-span vertex quantization, same union-find, same
1%-of-faces component threshold, same 3% total cap, same value filter inside
the face loop, same vertex re-pack — and run on the payloads the browser
actually fetches.

| Payload | Components | Faces in | Faces kept | Dropped |
|---|---|---|---|---|
| Wireframe display mesh (`sdk/geometry/b52.stl`, 13,784 facets -> 5,241 display faces) | 5,213 + 28 | 5,241 | **5,213** | 28 (0.53%) |
| Painted body (served `b52_field.json`) | 15,592 + 52 + 40 | 15,684 | **15,592** | 92 (0.59%) |

Both drops are far inside the 3% cap, so no real geometry can be reached.

**Alignment on the survivors, proved rather than asserted:**

- Every surviving face still carries the value of the source face it came
  from: `values_aligned = true` for the painted body.
- Every surviving face's three corners still sit at exactly the same
  positions after the vertex re-pack: `corner_positions_preserved = true`,
  worst corner error **0.0**. This is the check that catches a broken remap,
  and the unit tests include the two mutations (a shifted value list, a
  rotated index remap) that must make it fail.
- The filtered surface still reads as a physical field: neighbour-face
  correlation **r = 0.954** after the filter, against 0.952 before it.

Served-JSON integrity: the payload was recomputed from the case and compared
value for value — 15,684 values, identical `triangles_shown`, identical
window, **max value difference 0.0**.
