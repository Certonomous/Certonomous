# Act C screen data products — battery module

Vector figures and their underlying numbers for the module screens, built from
the run that already landed. **Nothing here solves anything**; the generator
reads the existing time directories and writes files a later display mission can
render without re-deriving a single number.

Generated by `docs/campaigns/T-family/demo/figures/make_act_c_screens.py`.

## Every source artifact

| Source | Path |
|---|---|
| Case, 181 time directories, 0–900 s | `verification/runs/T-family/T25_MODULE_runs/T25_MOD_L1/` |
| Mesh — 960 finite-volume cells, region `module` | `verification/runs/T-family/T25_MODULE_runs/T25_MOD_L1/constant/module/polyMesh/{points,faces,owner,neighbour,boundary}` |
| Temperature fields | `<case>/{0,30,60,120,300,900}/module/T`, and all 181 `<t>/module/T` for the histories |
| Channel-face boundary values | the `channelFaces` entry of `boundaryField` in each `<t>/module/T` |
| Reader — parsing and geometry, imported not re-implemented | `verification/runs/T-family/T25_MODULE_runs/analyse_t25.py` |
| Case constants, provenance and stated simplifications | `verification/runs/T-family/T25_MODULE_runs/T25_MOD_L1/CASE.txt` |
| Builder | `verification/runs/T-family/T25_MODULE_runs/build_t25.py` |
| Prior measured values, cross-checked against | `docs/campaigns/T-family/demo/README_SOURCES.md` |

Nothing is taken from probe output. Two of the three probe points in
`system/controlDict` sit exactly on internal mesh faces and snap to different
cells on a geometrically symmetric module; every per-cell number here is a
volume average over the 120 mesh cells of that cell instead.

Field minimum and maximum at each snapshot, in kelvin, read off disk:

|---|---|---|---|
| 0 | 293.000000 | 293.000000 | 0.000000e+00 |
| 30 | 293.057391 | 293.059998 | 2.607112e-03 |
| 60 | 293.110800 | 293.119198 | 8.398210e-03 |
| 120 | 293.130710 | 293.150095 | 1.938488e-02 |
| 300 | 293.184684 | 293.233103 | 4.841946e-02 |
| 900 | 293.295253 | 293.449031 | 1.537775e-01 |

The shared colour scale is therefore 293.000000 … 293.449031 K and nothing is
clipped at either end. The hottest point anywhere is 293.449031 K at 900 s, at
the insulated casing.

Peak and time to peak are in `actc_per_cell_table.csv`. Every cell peaks at the
last sample, 900 s: end cells 1 and 8 at 293.419751 K (0.419751 K above
coolant), interior cells 2–7 at 293.309239 K (0.309239 K above coolant). The
spread is monotone and reaches 0.110512 K at 900 s.

## There is no outlet temperature, and none has been invented

The cooling channels are **not resolved as a fluid region**. The case's own
region list is `fluid ()` — empty — and `solid (module)`; the only patches on
the mesh are `channelFaces`, `casingWalls`, `ends`, `front` and `back`, and
`channelFaces` carries a convective coefficient rather than a coupled fluid
interface. There is no inlet, no outlet and no coolant stream, so **no outlet
coolant temperature exists to be plotted**. The uniformity figure says this on
its face and shows the quantity that *is* defined — the heat removed at the
channel-facing surfaces, 22.1230 W at 900 s against a cruise input of 32 W.

This is a genuine gap in what these screens can show, not a rendering choice.

## The uncertainty column

One mesh and one time step were run in this configuration, so no discretisation
error estimate is available and the column says so rather than carrying a number
nobody measured. The peak is the largest of 181 samples written every 5 s, so
the time to peak is resolved to 5 s. A separate comparison of time-step size is
being produced elsewhere and is deliberately not anticipated here.

## Instrument checks before any of this was drawn

Two, both passed, both re-run every time the generator runs — it exits rather
than write a figure if either fails.

1. **Shared parser.** +1.000000 K planted on all 960 cells at 900 s; the reader
   saw +1.000000 K on the per-cell mean and +60000.0000 J of stored energy
   against an expected +60000.0000 J.
2. **Snapshot extractor.** +2.500000 K planted in one known mesh cell (index
   137) at 300 s; the extractor saw +2.500000 K in that cell and 0.000e+00 K
   change anywhere else.

A reader never shown able to see a change cannot be trusted with a zero, so
neither figure set is drawn until both plants are seen.

## Geometry guard

The generator re-asserts, in its own code path rather than by trusting the
reader's, that the mesh has 960 cells, a total volume of 0.024000 m³, a
channel-facing area of 1.4000 m², and exactly 120 mesh cells in each of the
eight module cells. It exits on any mismatch.

## Redrawing without re-deriving

Every figure can be rebuilt from the CSV and JSON files alone. The snapshot CSV
carries each mesh cell's rectangle, so the field frames redraw from the real
mesh geometry — never from a surface tessellation.
