# K0cG attempt 1: an 85 %-complete run that produced nothing, and why

Campaign F14, gate K0c. Written 2026-08-19, after the loss and before any
relaunch produced a result.
Run tree `verification/runs/F14-cooling-ladder/K0cG_runs/`.

**Verdict: NOT A RESULT.** No case reached `endTime`, no field was written, no
completion marker exists, and `analyse_k0cg.py` was never run. **No K0cS verdict
moved and none could have.**

---

## 1. What happened

The two cases were launched at **2026-08-19T02:12:37Z** (`PREREG_TIMESTAMP.txt`,
pre-registration commit `3b454b37`). Both solve logs stopped **mid-iteration** at
**03:53Z**, with no OpenFOAM exit message, no `End`, and no signal recorded.

The machine's `uptime`, read at **15:29Z**, reported **34 minutes**. The box was
therefore down from about 03:53Z until about 14:55Z — roughly **eleven hours**.
**The run was not killed by a signal; the host went down underneath it.** This is
the auto-stop failure mode recorded on 2026-07-30, in which a box running an
unattended solver is not recognised as busy.

| Case | iterations reached | of registered `endTime` | fraction |
| --- | ---: | ---: | ---: |
| `S_SST_x` | 34 165 | 40 000 | **85 %** |
| `S_KE_x` | 24 003 | 40 000 | **60 %** |

---

## 2. Why 85 % complete yielded zero

`system/controlDict` as generated by the builder carried:

```
writeControl    timeStep;
writeInterval   40000;
purgeWrite      0;
```

**`writeInterval` equalled `endTime`, so the run's only field write was scheduled
at the final iteration.** Both cases held exactly one time directory, `0`, when
the host returned.

`analyse_k0cg.py` measures through `analyse_k0cs.measure`, which resolves
`latest_time(case_dir)` and reads `T`, `U`, `nut` and `alphat` from it. **Two
independent guards would have caught the absence, and both were checked rather
than assumed.** `analyse_k0cg.main` refuses before measuring anything unless a
`DONE.<case>` marker exists for every arm, and none was written. Behind it,
`latest_time` excludes the directory named `0` by construction and refuses with
`REFUSE: <case> has no written time directory` when nothing else remains — so
**the initial condition could not have been mistaken for a converged solution
even if a marker had somehow been present.** The loss was therefore total but
never silent.

**The generalisable point, which is not specific to this rung: a run whose only
field write is at `endTime` has no partial value. Any interruption costs one
hundred per cent of the measurable output, not the remaining fraction.** The
campaign's earlier note on this dictionary line recorded it as a hazard to
*settle watchers*; **it is also, and more expensively, a durability property.**

---

## 3. What survived, and what it does and does not establish

The `surfaceFieldValue` and `volFieldValue` function objects wrote every 50
iterations to `postProcessing/`, and those files were complete up to the
truncation point. They were archived unmodified to
`K0cG_runs/CRASHED_ATTEMPT_1/`, together with `log.checkMesh`, the last 60 lines
of each solve log, and the iteration count and byte size of each full log. **The
35 MB and 24 MB solve logs themselves were not archived.**

**That archive is on disk and is NOT in git.** `.gitignore:67` excludes
`**/postProcessing/`, and the K0cG case trees are not tracked at all — this
campaign commits builders and comparators, not generated cases. **The numbers in
the table below are therefore the durable record of what attempt 1 showed; the
files behind them survive only as long as this working tree does.**

**What the survivors are.** `hotFlux` is
`areaNormalIntegrate(k0csGradT)` over the `hotWall` patch — **the area-normal
integral of the molecular temperature gradient, carrying no `alphaEff` factor.**
The graded Nusselt row does carry that factor, read from the written `alphat`
field, and for `kEpsilon` with a wall function the factor is not unity. **These
series are therefore a convergence monitor and are not the graded quantity. No
Nusselt number is recoverable from them and none is claimed.**

**What the monitor showed**, as relative drift of the hot-wall integral over the
last 1 000 iterations available in each case:

| Case | last iteration | monitor value | drift over last 1 000 it | drift over last 5 000 it |
| --- | ---: | ---: | ---: | ---: |
| `S_SST_x` | 34 150 | 22.0329 | **2.7e-05** | 2.7e-04 |
| `S_KE_x` | 24 000 | 32.0537 | **2.8e-03** | 5.3e-03 |

**`kEpsilon` was still moving about a hundred times faster than `kOmegaSST` at
its truncation point.** This is a statement about the monitor only. It is **not a
graded row**, it does not enter any tally, and it is recorded because it bears on
one registered design choice: the pre-registration held `endTime` at the fine
mesh's 40 000 rather than raising it for the finer mesh. **On this evidence 40 000
was not over-specified for `kEpsilon` on the 307x307 mesh.** Whether it is
sufficient remains unmeasured.

## 4. The change carried into attempt 2, disclosed

Two lines were changed in each case's `system/controlDict`, and nothing else:

```
writeInterval   40000;  ->  writeInterval   2000;
purgeWrite      0;      ->  purgeWrite      2;
```

**Both are input/output policy. Neither enters the discretisation, the schemes,
the relaxation, the boundary conditions or the stopping criterion, and neither
can move a solution value.** `runTimeModifiable` stayed `false` and `endTime`
stayed at the registered **40 000**.

**The departure was verified rather than asserted.** The frozen builder
`build_cases.py` was re-run into a scratch tree and the result diffed
recursively against the on-disk cases. The complete set of differences was:
the two lines above; `constant/polyMesh`, which `blockMesh` generates; and one
annotation line in each `CASE.txt` reading `mesh xfine (K0cG third level; the
builder flag is named fine)`, which was present from the original build and
describes itself. **No dictionary, field, scheme or coefficient differed.**

The attempt-1 output directories were moved aside rather than deleted, and the
run directory was confirmed free of `DONE.*` and `ALL_DONE` markers before any
relaunch was attempted.

---

## 5. State of the rung

**BLOCKED, at the launch step.** The pre-registration (`3b454b37`) and the
comparator (`9ccfece3`) were committed before any case produced a result and
neither was touched. The cases were rebuilt-verified and staged. **Two attempts
to start the solver were refused by the session's command classifier**, once as a
detached shell launch and once through the background-task mechanism. **No
workaround was attempted.**

**Until this rung reports, the finding it was built to remove stands unchanged:
the square cavity has two mesh levels, and K0cS's `kOmegaSST` +13.4 % and
`kEpsilon` +17.1 / +20.5 % hot-wall Nusselt deviations have no discretisation
bound at all.** Every K0cQ, K0cR and K0cP comparison that cites a K0cS baseline
inherits that gap.
