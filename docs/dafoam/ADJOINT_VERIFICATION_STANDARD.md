## 1. FD-vs-adjoint relative error per design variable, with the plateau proof

**Definition.** For each registered design-variable component `i`, the reverse-AD total derivative `g_adj[i] = dJ/dx_i` and a central finite difference at step `h`,

`g_fd[i](h) = (J(x + h e_i) − J(x − h e_i)) / (2h)`, `ε_i = |g_fd[i] − g_adj[i]| / |g_fd[i]|`,

plus the aggregate vector-relative error `‖g_adj − g_fd‖₂ / ‖g_fd‖₂` over the graded components, named as a statistic (never compared with a published per-component average, `DAFOAM_CHARTER.md` §2). The step is proved to lie in a plateau per component: `|g_fd(h_nb) − g_fd(h)| / |g_fd(h)| ≤ τ_plateau` for at least one neighbouring step a decade away. Definitions and the measurement's own caveats: `V_STANDARD_FD_VS_ADJOINT.md` §1 (the statistic), §4 (step selection), §5 (plateau per component at the graded run's own primal tolerance), §6 (the three FD-noise caveats N-D3 / N-D13 / N-D15), §7 (the trivial baseline at a deliberately wrong step, `DAFOAM_CHARTER.md` §4), §9 (the endpoint rule — every optimisation FD-checks at its FINAL design point, `DAFOAM_CHARTER.md` §9).

**Measurement in DAFoam terms.** Reverse: `prob.compute_totals(of=[…], wrt=[…])` on the mphys `Top` (OpenMDAO `mode="rev"`; DAFoam's `DAFoamSolver.solve_linear` → `solverAD.solveLinearEqn(ksp, dFdW, psi)` at `mphys_dafoam.py:547`, then `solverAD.calcJacTVecProduct` for `ψᵀ∂R/∂x`), written by the item's instrument to a JSON artefact (`<arm>/d15_X.json` in the D15 family, `d5_fd_endpoint.py` outputs in D4/D5). FD: `prob.set_val(dv, x ± h e_i)` + `prob.run_model()` per sign per step, every primal a cold copy (`DAFOAM_CHARTER.md` §6 warm-start rule), the table written row by row with `fsync` to a JSONL and the final JSON (`d15_F.json`). The artefacts that prove it: the X JSON, the F JSON/JSONL, the arm logs carrying the instrument's terminal marker, and the ledger row with `rc` from `docker inspect` (rule 4). The planted-zero control (rule 3) is a `CTRL` component: derivative exactly `0.0` and a planted twin exactly `PLANT/(2h)`, written, re-read from disk by the instrument and again by the grader (`d15_xf.py:240-268`, `d15_grade.py: ctrl_control, grader_plant_control`).

## 2. The dot-product (duality) test

**Definition.** DAFoam v4 provides two AD modes of the same discrete residual `R(w, x)` and function `J(w, x)`: forward (`libs/ADF`, CoDiPack tangent) and reverse (`libs/ADR`, CoDiPack tape). For any state direction `δw` and any adjoint seed `ψ` the linearised operators must satisfy the transpose identity

`⟨ψ, (∂R/∂w)·δw⟩ = ⟨(∂R/∂w)ᵀ·ψ, δw⟩`   *(residual level; likewise with `∂R/∂x` and a design direction `δx`)*,

and at the total-derivative level, for any design direction `δx` and any function seed `J̄`,

`⟨J̄, (dJ/dx)·δx⟩ [forward: ADF]  =  ⟨(dJ/dx)ᵀ·J̄, δx⟩ [reverse: ADR]`.

Each side is one inner product; the discrepancy `ε_dp = |L − R| / max(|L|, |R|)`. It is a **code-verification** test of the transpose (the reverse code is the exact adjoint of the forward code **of the same discretisation, mesh and linear-solver tolerances**), independent of any finite difference and of any step-size question: an FD comparison has a noise floor (§1), the duality test has none beyond linear-solver tolerance and round-off, so a 1e-6 discrepancy here is a defect while a 1e-2 FD discrepancy may be noise. Its planted control (rule 3) is a **deliberately wrong transpose** — e.g. the reverse product with `ψ` sign-flipped — which must read outside the band before the clean pair is read.

**What an np-dependence would mean.** `ε` inside the band at np = 1 and outside at np > 1 with the same seeds locates a broken transpose **at the partition boundary** (halo exchange or a parallel reduction on one tape but not the other) — a decomposition defect in the AD path, the class the family has met from the outside (A4: np=4 `scotch` 8.95 % against `simple` 0.00054 %, §3) without ever holding the instrument that names it from the inside. ## 3. np-invariance — gradient invariance across rank counts and decompositions

**Definition.** The same gradient at the same design point on the same mesh and image at np = 1 (the serial reference) and at np > 1 (and, at fixed np, across `scotch` / `simple` / `hierarchical`), with the objective beside it:

`s_J(np) = |J(np) − J(1)| / |J(1)|`, `s_g(np) = ‖g(np) − g(1)‖₂ / ‖g(1)‖₂`, and per component `sign(g_i(np)) = sign(g_i(1))`,

with `g` the concatenation of the registered totals (CD w.r.t. `shape` and `patchV`; CL likewise, graded separately). `DAFOAM_CHARTER.md` §5 `:158-161` binds the disclosure: *"A gradient verified at one np is a statement about that np and is never carried to another"*; `V_STANDARD_FD_VS_ADJOINT.md` §8 `:427-468` (an FD reference is part of a configuration, not a property of a case). The test is meaningful only with deterministic partitioning (`PARALLEL_GATE_DOCTRINE.md:36`: pin the method).

**Measurement in DAFoam terms (the registered rung AV-1, `cases/dafoam/ladder-a/A1/curriculum_AV1/`).** One case (A1 NACA0012, 4,032 cells, `DASimpleFoam`), one mesh generated once, three X arms per row — `mpirun -np 1|2|4` of the §1 X instrument with `system/decomposeParDict` `numberOfSubdomains = np`, `method scotch` (DAFoam runs `decomposePar` itself at np > 1, `pyDAFoam.py:1454 runDecomposePar`), CD and CL totals w.r.t. `shape` + `patchV` at the baseline — and both rows (two-row rule). The artefact per arm: `<arm>/av1_X.json` carrying the totals, `CD`/`CL`, `nprocs`, and the per-processor cell counts read from `decomposePar`'s output (the partition record, D4 G8's form). The comparator reads the serial arm as the reference and never averages across np.

## 4. Complex-step

**Definition.** `dJ/dx_i = Im[ J(x + i·h·e_i) ] / h` with `h ~ 1e-20` — no subtractive cancellation, no step-size question, no noise floor: an exact reference to round-off (ADflow's authors reach 11–12 digits with it, `V_STANDARD_FD_VS_ADJOINT.md:79`; PAS 2019 §5.1). Pass form when it exists: `|g_adj − g_cs| / |g_cs| ≤ band D` per component, 0 flips, with the complex primal converged to the same residual as the real one.

**What a complex DAFoam build requires — stated so the `BLOCKED` is honest.** DAFoam's AD is CoDiPack operator overloading over OpenFOAM-AD, built as two extra platforms beside the real one: `OpenFOAM-AD/platforms/linux64GccDPInt32OptADF` (forward, `-DCODI_ADF`) and `…OptADR` (reverse, `-DCODI_ADR`), each with its own `libDASolver{ADF,ADR}.so` and `pyDASolvers{ADF,ADR}.so` — the three trees both images carry (§0 table below). ## 5. Verdict mapping into the fixed vocabulary, and the two-row rule (shipped / patched)

**The vocabulary.** `PASS` / `GATE REACHED` / `GATE FAIL` / `NOT A RESULT` / `BLOCKED` / `PENDING`, defined in one place (`CLOSURE_MODELLING_CHARTER.md` §12, adopted for DAFoam by `DAFOAM_CHARTER.md` §8). For every check above the mapping is the same shape: **`PASS`** inside the frozen band with every planted control seen; **`GATE FAIL`** outside it, the component and row named, never re-banded; **`NOT A RESULT`** on a comparator refusal (completion rule 4, age guard, planted zero not seen, no plateau, fewer than the registered minimum of graded components, an unconverged primal or adjoint); **`BLOCKED`** when the instrument cannot run (an adjoint that does not return, a library that does not import, a build that does not exist, an arm that cannot fit); **`GATE REACHED`** only for an optimiser stopped on a registered cap after meeting a registered intermediate threshold (`DAFOAM_CHARTER.md` §9), never for a gradient check; **`PENDING`** for a registered, unrun row (`PENDING: <path>`, a queue state — rule 1). A verdict is valid only against a falsifier that was in the pre-registration before the run.

**The two-row rule.** Every gradient verdict is measured twice — against the shipped toolchain image and against whatever was patched — each row carrying the image tag, image ID and the md5 of the patched `.so`; a patched row never replaces a shipped row (`DAFOAM_CHARTER.md` §6 `:201-215`; the IDWarp rotation patch moves a reverse-mode derivative by seven orders of magnitude on the defect's DOFs while the version string reads `2.6.2` either way). Toolchain identity by library hash: D4 `G9` (`1697ea49`), D7FR two distinct `.so` md5s asserted `True` (`curriculum_D7FR/RESULTS.md:58-60` @ `2a93ff27`); the D15 family's G9 reads three sources per arm (ledger digest, the container's `D4S_IDWARP_SO_MD5:` print, the artefact's in-process md5). Inventory: `docs/dafoam/TOOLCHAIN_INVENTORY.md`. **Why it is a verification check and not bookkeeping:** the two rows are two implementations of the same derivative on the same case; their per-component divergence is a code-verification signal with no FD noise floor — where both agree with FD and with each other (D7FR, 0.000 % on every component) the derivative is a property of the case; where they disagree (A1 baseline: shipped `GATE FAIL` 11.4274 % with a flip, patched `PASS`; A5: shipped 46.84 % with two flips) the defect is located in the toolchain and the FD table says which row is right. **The composition:** both rows graded independently on the same band; divergence reported per component with its number, never gated; the item reads `PASS` only if every bought row is `PASS`; a shipped row that does not return is `BLOCKED` (D1 arm C @ `b10260a0`; B3 @ `3f8c6b13`), not a missing row; a row that was not bought is stated as not bought (D13 SHIPPED, `curriculum_D13/RESULTS.md:20` @ `15767999`), never inferred. §2, §3 and §4 inherit this rule: AV-1 and AV-2 buy both rows.

**Status in this family — DONE, standardised.** D7FR @ `2a93ff27` (both `PASS`); A1 baseline @ `be35dcad` / D1 @ `b10260a0`; A5 @ `35171866`; A2 grading confirmation @ `35171866` with D4 @ `1697ea49`; D4-SHIPPED @ `b26b875c` (`NOT A RESULT` on its grader path); D15 @ `8fc2bdeb` and D16 @ `3ccb0c81` registered on both rows. **Not done:** the unsteady line (no FD row exists on either image).
