# 🔴 TWO FINDINGS FROM L3 — AN INSTRUMENT DEFECT, AND A STRUCTURAL LIMIT OF THE FROZEN OPTION SET

## FINDING 1 — **pyHyp EXITS 0 ON A HARD FAILURE.** The rc is worse than useless; it is inverted.

L3's first attempt (`N` = 209, pGridRatio 1.1) printed:

> `Erorr: The supplied pseudo grid ratio is too large. It must be less than   1.0534135893713681`

and then **exited with status 0**. The wrapper faithfully recorded `PYHYP_RC=0`. **No volume mesh was
produced.** Artifact: `L3/pyhyp_rc.txt` reads `PYHYP_RC=0`, and `L3/volumeMesh.xyz` does not exist.

**I was briefed that `docker run` exits 0 regardless of the work's rc. This is a level deeper:
the WORK ITSELF exits 0 on a hard failure.** Capturing rc inside the container — the repair the
`59dfc5232` probe adopted — **would NOT have caught this.**

**What did catch it** was the extrusion marker's TWO-condition test, which requires the rc AND the
script's own end-of-run string:

    if [ "$r" = "0" ] && grep -q "PYHYP_WROTE" pyhyp.log; then ... > DONE_EXTRUDE

`DONE_EXTRUDE` is correctly ABSENT. **A completion claim must rest on the product's existence, never
on a status code** — the principle rule 4's age guard already encodes, here paying for itself on a
tool the lab had already cleared.

*(pyHyp's own message carries the typo `Erorr`, quoted verbatim so it can be grepped.)*

## FINDING 2 — **A SINGLE `pGridRatio` CANNOT SPAN AN r = 2 FAMILY IN `N`.** Measured, not argued.

pyHyp requires `pGridRatio` < the level's own grid ratio. The grid ratio is what is needed to reach a
FIXED `marchDist` in `N`-1 layers, so **it necessarily falls as `N` rises** — and `N` doubling twice
is exactly what this family is.

| level | `N` | pyHyp's printed **Grid Ratio** | probe's `pGridRatio` = 1.1 admissible? |
|---|---|---|---|
| L1 | 53 | **1.2335** | yes, by 0.1335 |
| L2 | 105 | **1.1100** | **yes — BY 0.0001** |
| L3 | 209 | **1.0534135893713681** (pyHyp's own bound) | **NO — INADMISSIBLE** |
| *(probe, `N` 53 on the 44,544 surface)* | 53 | 1.2704 | yes |

🔴 **L2 CLEARED THE CONSTRAINT BY ONE PART IN TEN THOUSAND.** Had the margin gone the other way the
ladder would have stopped at L1, and nothing in the frozen registration anticipates this constraint
at all. **The registration's assumption that the probe's options transfer unchanged across the family
is refuted by measurement** — not because the options are wrong, but because one of them is bounded
by a quantity the refinement itself moves.

### The repair, and why it is not gate-fitting

`pGridRatio` is **not a gate, threshold, cap or label** — rule 2 closes those, and this is none of
them. It is a precondition for the extruder to start, and **pyHyp printed the exact admissible
bound**, so the fix is deterministic rather than tuned. It cannot be fitted to a gate outcome
because it is chosen before any quality number exists.

**`pGridRatio` = 1.03 is adopted for ALL THREE LEVELS, and L1 and L2 are REBUILT with it**, so the
family is generated by ONE option set. Building L3 alone at a different value would have made the
three levels incomparable, which would defeat the entire purpose of a nested family. The
pGridRatio = 1.1 logs for L1/L2 are preserved under `VARIANT_pGridRatio_1.1/` because the first
reported numbers were measured there.
