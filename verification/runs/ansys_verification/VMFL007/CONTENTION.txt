TWO DESIGN GAPS, BOTH MEASURED, FOR THE SAMPLER'S NEXT VERSION.

GAP 1 -- NO LIVENESS CHECK ON THE WATCHED RUN.  The sampler distinguishes "the
run ENDED before the threshold" (it greps for `^End$` and correctly records
MISSED) from nothing else. It cannot distinguish "the log has not appeared YET"
from "the log will NEVER appear", because it never asks whether the run that was
supposed to write it is still alive. So a run that DIES rather than COMPLETES
leaves the sampler burning its whole 7200 s deadline before it records anything.
Measured here: at termination it still had 3998 s (66.6 min) of that deadline to
burn. THE FIX: take the launcher/solver pid as an argument, and on each pass, if
that process is gone AND the log still does not exist, emit MISSED and exit
immediately instead of waiting out the deadline.

This is the INVERSE of the lesson that created the sampler. The sampler exists
because a lane cannot be a watcher -- a task must never depend on an agent being
alive at a future instant. It fixed that and introduced the opposite failure: an
OS-level watcher OUTLIVES its subject.

GAP 2 -- THE SHARED SCRIPT PATH WAS OVERWRITTEN IN PLACE UNDER A RUNNING
INSTANCE, AND THAT SILENTLY DESTROYED THE MISSED BRANCH.  This is the more
serious of the two and it is verified by byte offset, not inferred.
  - pid 2241095 was launched against the 2935-byte text committed at 8a45cd7b
