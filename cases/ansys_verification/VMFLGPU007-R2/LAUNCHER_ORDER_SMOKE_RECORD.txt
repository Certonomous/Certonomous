PART 2 -- A DEFECT THIS SMOKE FOUND, WHICH NOTHING ELSE WOULD HAVE
================================================================================
The smoke would not run at all at first.  Triaged rather than worked around, and
the cause is in the launcher's own environment step:

  OpenFOAM v2606's etc/bashrc ends with
      . "$WM_PROJECT_DIR/etc/config.sh/setup" "$@"
  and that chain reaches, at etc/config.sh/setup line 205,
      _foamEtc -config  paraview -- "$@"  # Pass through for evaluation
  which SOURCES any positional argument that resolves to a *.sh file.

MEASURED, driving it both ways on the lab box:
  argument is a DIRECTORY      -> harmless; blockMesh stays on PATH
  argument is a path to *.sh   -> THAT FILE IS EXECUTED INSIDE THE BASHRC, with
                                  none of the calling script's variables set, and
                                  PATH is left without FOAM_APPBIN
The failure is silent in the worst way: with the customary
`. "$OF_BASHRC" >/dev/null 2>&1` the sourced file's fd manipulation leaves the
caller's stdout on /dev/null, so every later echo -- including the ABORT
messages -- disappears.  That is how a 45-minute triage started from "blockMesh:
command not found" in a log written by a script that printed nothing.

THE LAUNCHER WAS NEVER EXPOSED, and the reason is luck rather than design: its
only positional is RUN_ROOT, a DIRECTORY.  R1 ran to completion on the GPU
instance for exactly that reason.  But it is a live path from an argument to code
execution inside the launcher, and it costs one line to close.

REPAIR, made PRE-FREEZE and disclosed here: `set --` immediately before the two
environment sourcings (line 203 of run_vmflgpu007_r2.sh).  $1 is read once, at line
86, long before; measured: 0 uses of $1, $@ or $* at script level after that.
