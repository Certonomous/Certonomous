## 0. SCOPE — WHICH FORM OF THE TEST, AND WHY

**The identity tested.** For a scalar function `J` and a design vector `x`, the forward tangent along the unit direction `e_k` and the reverse total's `k`-th entry are the same number by the transpose identity: `⟨1, (dJ/dx)·e_k⟩ [ADF] = ⟨(dJ/dx)ᵀ·1, e_k⟩ [ADR]`. This is the total-level dot-product/duality test with `δx = e_k`, `J̄ = 1`, per registered component — exactly the check DAFoam's authors run (`tests/testFuncs.py:33-50`, md5 `fb11e906…`, in the shipped image; PAS 2019 §5.1's 10-digit forward-AD reference, `DAFOAM_CHARTER.md` §2 `:66-73`). **The residual-level form with random `ψ` and random `δw` is `BLOCKED` at DAFoam v4's Python API** (standard §2, v1.0a: `calcJacTVecProduct` is reverse-only, the mphys forward hooks `om.issue_warning` and fall through, the v3 names `calcdRdWTPsiAD`/`calcdRdXvTPsiAD`/`calcdFdW` are absent) and is not attempted here.

**Why this test is worth buying even where FD rows exist.** An FD comparison has a noise floor (D13's 0.26 % is FD noise, not adjoint error); the forward tangent has none — a 1e-5 discrepancy here is a defect. And the two AD modes take **different IDWarp code paths** for an FFD component (`warpDerivFwd` through `calcFFD2XvSeeds`, `pyDAFoam.py:1376`, against `warpDerivBwd` in reverse), so on the SHIPPED row the rotation defect that flips A1's idx6 in reverse (`reverify_patched_idwarp_np1/RESULTS.md:38` @ `be35dcad`) is expected to appear as a **forward/reverse disagreement on `shape[6]`** — P2 registers exactly that.
